# Фрагмент — как отдать генеративку в чужую вёрстку

## Зачем этот скилл

Наши генеративные сцены — канвасные движки с настроенной физикой, изингами, палитрой и десятками
ручек, которые доводились глазом. Если отдать такую сцену как задачу («сделай нам шар из дисков»),
верстальщик — человек или Design — будет её пересобирать. Получится похоже и хуже, а всё, что мы
крутили руками, потеряется.

**Разделение труда:** страницу строит он, генеративку вставляет готовой.
Это не вежливость, это единственный способ не потерять настройку.

## 1 · Контракт фрагмента

Один блок = одна папка:

```
fragments/<NN>-<имя>/
   index.html      ← single-file, zero-dependency, работает по file://
   PASSPORT.md     ← без него фрагмент вставят неправильно
   preview.png     ← как он выглядит, чтобы верстальщик видел цель
```

**index.html обязан:**
- открываться двойным кликом, без сборки и без сети (см. `single-file-delivery-canon`);
- понимать `?embed=1` — прятать панель, полки, кикеры, подсказки; остаётся чистая сцена;
- иметь фон, совпадающий с грунтом страницы, чтобы не резать композицию рамкой;
- держать `?theme=night` (или что у проекта вместо ночи);
- уважать `prefers-reduced-motion`;
- инкрементить счётчик кадров и выставлять `__READY` — приёмка меряет живость, а не скриншот.

**Полезное, если сцена ведёт повествование:**
- `?p=0.35` — показать кадр на такой-то доле сборки, чтобы проверять без скролла;
- внешний API вида `Scene.set(path, value)` — одна дорога в состояние, та же, что у панели.

## 2 · Заморозка пресета — отдельный шаг ДО отдачи

Настройки, доведённые глазом, переносятся в дефолты файла и фиксируются. Это не «дефолты на глаз»,
это принятое решение, и в паспорте оно помечено как замороженное.

**Как замораживать:** отдельный оверрайд-файл, который сборщик доклеивает после приложения.
Движок остаётся общим инструментом с панелью, фрагмент — его застывшим срезом под конкретную секцию.
Понадобилась другая настройка — не правим вёрстку, а пересобираем фрагмент.

**Грабля:** если пресет остался «как в билдере», при следующей правке билдера фрагмент молча уедет.

## 3 · Паспорт — что в нём обязано быть

Образец: `references/PASSPORT_EXAMPLE.md`.

| Раздел | Что пишем |
|---|---|
| Что это | одной фразой, и что означают элементы сцены |
| Как вставлять | готовый кусок разметки с `<iframe … ?embed=1>` |
| Пропорция и минимальная высота | числами. Без этого получишь сплющенную сцену |
| Параметры адреса | таблица: что делает каждый |
| Привязка к скроллу | готовый скрипт целиком, копипастой (см. §4) |
| **Что ЗАМОРОЖЕНО** | перечислить. И прямо: менять нельзя ни CSS-фильтром, ни `transform`, ни масштабом iframe |
| Что фрагмент делает сам | приезд, ховер, клик — чтобы верстальщик не дублировал это своими средствами |
| Состояния | загрузка · reduced-motion · клавиатура · узкий экран · тёмная тема |
| Живость | имена счётчиков для приёмки |

**Тон паспорта:** запреты пишем прямо и с причиной. «Не масштабировать iframe» без причины
проигнорируют; «масштабирование ломает пропорции подписей, они рассчитаны в пикселях» — нет.

## 4 · Привязка к скроллу

Фрагмент **сам скролл не слушает**. Внутри iframe он не видит родителя, а `IntersectionObserver`
внутри iframe меряет свой вьюпорт, а не страницу. Ведёт страница:

```html
<script>
(function () {
  var wrap  = document.querySelector('.fragment-mount');
  var frame = wrap.querySelector('iframe');
  function tick() {
    var r = wrap.getBoundingClientRect(), vh = window.innerHeight;
    var p = Math.max(0, Math.min(1, (vh - r.top) / (vh + r.height)));
    frame.contentWindow.postMessage({ type: 'es:progress', value: p }, '*');
  }
  addEventListener('scroll', tick, { passive: true });
  addEventListener('resize', tick);
  tick();
})();
</script>
```

Внутри фрагмента:

```js
window.addEventListener('message', function (e) {
  var d = e && e.data;
  if (d && d.type === 'es:progress' && typeof d.value === 'number') setProgress(d.value);
  if (d && d.type === 'es:replay') { scrollDriven = false; replay(); }
});
```

🔴 **Фолбэк обязателен.** Пока сообщение не пришло, фрагмент играет сборку сам по таймеру.
Иначе забытый или сломанный скрипт даёт мёртвую секцию, и виноватыми будем мы.

## 5 · Правила, которые идут в ТЗ верстальщику

1. **Смысл секции читается БЕЗ фрагмента.** Если сцена иллюстрирует семь пунктов — эти семь пунктов
   обязаны быть в разметке текстом. Фрагмент иллюстрирует, а не заменяет. Проверка: выключить
   скрипты, секция всё ещё понятна.
2. **Место под фрагмент резервируется всегда** — заданной пропорцией, а не «по содержимому».
   Иначе композиция прыгает при загрузке.
3. **Ничего поверх канваса.** Оверлеи, градиенты «для красоты», подписи вёрсткой поверх сцены —
   нет: подписи внутри участвуют в раскладке выносок и о внешних не знают.
4. **Не обрезать по высоте** — сцена скомпонована целиком.
5. **Состояние error** — если фрагмент не поднялся, на его месте тихая заглушка на токенах,
   без красного алерта.

## 6 · Приёмка фрагмента в чужой вёрстке

- Пропорция соблюдена, фрагмент не отмасштабирован и не обрезан.
- Скролл-скрипт подключён; при выключенном скрипте секция всё равно живая.
- Ничего не наложено сверху.
- Счётчик кадров растёт — сцена живая, а не нарисована один раз.
- Смысл секции читается при выключенных скриптах.
- Тёмная тема и 390 px проверены отдельно.

## 7 · Когда фрагмент — плохая идея

- Блок обязан быть в потоке текста и переливаться с ним → это не фрагмент, а компонент вёрстки.
- Сцена должна брать данные из страницы в реальном времени → нужен не iframe, а inline-модуль
  с `mount(el, opts)`; тот же паспорт, другой транспорт.
- Блок появляется десятками на странице → iframe на каждый дорого, собирать в один канвас.
