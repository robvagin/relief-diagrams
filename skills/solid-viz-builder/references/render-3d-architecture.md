# 3D render architecture — векторная имитация объёма на 2D-canvas

Это ядро линии. Здесь — как проецировать, как СОРТИРОВАТЬ грани (главный источник багов) и как
оптимизировать. Всё выковано на Hexbin и Sunburst в сессии 2026-07-05.

## Проекция
```
rotY(p,yaw): x'=x·cos+z·sin, z'=-x·sin+z·cos            // поворот вокруг вертикали
rotX(p,tilt): y'=y·cos−z·sin, z'=y·sin+z·cos            // наклон
vT(v,cm)=rotX(rotY(v,yaw),tilt)                         // ориентация (нормали!)
toScr(x,y,z): q=vT(...); s=fov/(dist+q.z); {x:W/2+q.x·s, y:H/2−q.y·s, z:q.z}
```
- `y` — высота (объём растёт вверх). Земля — плоскость `y=0`.
- **Ближе к камере = меньше `q.z`.** Painter: рисуем far→near ⇒ сорт по `z` УБЫВАНИЮ.
- **Ключевой факт:** подъём по `y` МЕНЯЕТ `q.z` (`z' += y·sin(tilt)`). Значит глубину грани нельзя
  считать «по центру объекта на его высоте» — высота искажает глубину. Это причина всех багов ниже.
- **Дом = вид сверху ¾:** крышки (нормаль +y) видны, когда их `q.z<0`, т.е. при **отрицательном** tilt
  (≈ −28…−32). Наклон НЕ клампить.

## Правило сортировки (per-object vs interleave) — читать перед любым 3D-билдером

Есть две стратегии. Выбор — по тому, **пересекаются ли объекты по глубине**.

### A. Разделённые объекты на плоскости (Hexbin: башни, разнесённые по земле)
Объекты не переплетаются — каждый стоит на своём пятне земли. Тогда:
- **Ключ сортировки МЕЖДУ объектами = view-z НАЗЕМНОГО центра** `vT({x,y:0,z},cm).z`. **Без высоты.**
  Наземная глубина — инвариант: не зависит от того, смотрим сверху или снизу, и НЕ «прыгает» при
  вращении. (Ошибка, которую поймали: ключ по центроиду на `h/2` → высокая дальняя башня «выезжает»
  вперёд и перекрывает ближнюю. Лечится ключом по `y=0`.)
- **Внутри объекта** собираем все его грани (боковые + верх + **низ**) и сортируем по их собственной z.
  Нижняя крышка обязательна — иначе при повороте до вида снизу объект просвечивает.
- Порядок: объекты far→near; внутри каждого — его грани far→near.

### B. Вложенные / пересекающиеся объекты (Sunburst: концентрические дуги-кольца)
Высокое внутреннее кольцо ФИЗИЧЕСКИ переплетается по глубине с внешними (низ за передними кольцами,
верх над ними). Per-object сорт это упорядочить не может → **стенки высоких пропадают** (баг Роба).
Один большой полигон-стенка тоже не годится: у него одна усреднённая глубина. Решение:
1. **Тесселяция.** Каждый объект → мелкие квады:
   - верх/низ = K угловых секторов (`K=ceil(спан/0.14)`), плоские.
   - стенки = K угловых × **V вертикальных** (`V=clamp(ceil(h/0.2),1..5)`) — вертикальное дробление
     ОБЯЗАТЕЛЬНО, иначе высокий квад снова имеет искажённую центроид-глубину.
   - радиальные бортики = V вертикальных.
   Мелкий квад ⇒ центроид ≈ реальная глубина ⇒ painter корректен.
2. **Back-face culling.** Нормаль → view (`vT`); если `nView.z > 0.03` (отвёрнута) — не строим.
   Убирает дно, задние и внутренние стенки: меньше draw-call И нет overdraw-артефактов. Крышки
   двусторонние — видимую оставляем, отвёрнутую куллим (снизу вместо неё появляется нижняя крышка).
3. **ОДИН глобальный painter.** ВСЕ квады всех объектов в один массив, сорт по центроид-z far→near,
   один проход. Так высокая стенка честно перекрывается/перекрывает ПО КУСКАМ.

**Как выбрать:** объекты не накрывают друг друга в проекции при типовом ракурсе → A (дёшево). Есть
вложенность/наложение (кольца, стопки, плотная решётка высоких) → B. Sunburst = B, Hexbin = A.

## Швы и заливка
- **Seal-хайрлайн.** Соседние одноцветные квады, залитые раздельно, дают тонкие AA-щели фона. Лечим:
  каждый квад ЗАЛИВАЕМ и обводим ЕГО ЖЕ цветом (`lineWidth 0.6–0.7`). Щели исчезают, видимой сетки нет.
- **Рёбра (Edges toggle).** НЕ штрихуем внутренние швы тесселяции. Штрихуем только контур **верхней**
  грани объекта (INK, α≈.14–.16), вставленный в общий painter по глубине верха — определяет границы
  без сетки.

## Затенение (грани читаются как объём)
Ламберт по нормали. Свет — в view-пространстве (стабильно при орбите камеры):
```
LV = normalize({x:-0.34, y:0.62, z:-0.70})             // сверху-слева-спереди
lit(nWorld): n=vT(nWorld,cm);
  cull = n.z > 0.03
  sh   = amb + (1-amb)·max(0, n·LV)                     // amb = state.*.side (пол яркости)
faceColor = gray(base·sh)  |  для цвета: mix(base,'#000', (1−sh)·0.9)
```
Верх (нормаль +y) ярче, стенки падают по ориентации. `side`-слайдер = ambient floor (контраст объёма).

## Производительность («летало в вебе»)
- `layout*` (раскладка данных) КЭШИРУЕТСЯ — считается только на `dirty` (смена данных). Per-frame =
  проекция + cull + sort + draw.
- Тесселяция + cull: у Sunburst депт-3/бранч-4 ≈ **338 граней/кадр** после куллинга → sort+fill доли мс, 60fps.
- `dpr = min(devicePixelRatio, 2)`. Никаких тяжёлых аллокаций в кадре сверх массива граней.
- Bbox на каждую грань (`minx/maxx/miny/maxy`) — дёшев и нужен для depth-occlusion пилюль (см. другой ref).

## Чек причин, если «что-то с построением слоёв»
- Стенки высоких пропадают / дальнее перекрывает ближнее → ключ сортировки завязан на высоту → перейти
  на A (наземный ключ) или B (тесселяция+global).
- Просвечивает снизу → нет нижней крышки / нет back-face cull.
- «Прыгает» при вращении → ключ не монотонен (min(base,top) и т.п.) → взять чисто наземный z или global-per-quad.
- Тонкие щели → нет seal-хайрлайна.
- Плоско, не читается объём → нет ламберта по нормали.
