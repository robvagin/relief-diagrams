# Responsive Canon — как наш канон перестраивается по ширинам

Десктоп-истина = `WEB_UI_CANON.md` (контейнер 1320–1440, секции 80–104, hero 64–80…). Здесь — закон
перестроения вниз. Брейкпоинты канона: **360 · 768 · 1200+** (H5 интервью: три ширины параллельно,
не «десктоп, потом как-нибудь»). Формат правил: правило → когда → антипаттерн.

## R1 · Контейнер и поля
1320–1440 центр на ≥1200 → fluid с полями 32px на 768–1200 → поля 20px на ≤768 → 16px на ≤400.
**Антипаттерн:** фиксированный контейнер шире вьюпорта (горизонтальный скролл всей страницы) —
блокер сдачи.

## R2 · Типографика вниз
- Шкала через `clamp()`: hero 64–80 desktop → 40–48 tablet → 32–36 mobile (~×0.5 от десктопа).
  Шаги остальной шкалы сжимаются пропорционально, спокойный контраст ×1.2 сохраняется.
- **Body 16px НЕ уменьшается никогда.** На мобиле инпуты тоже ≥16px (iOS зумит фокус на меньшем).
- Трекинг ПЕРЕСЧИТЫВАЕТСЯ по фактическому кеглю (TYPOGRAPHY_CANON): заголовок, ужавшийся с 72 до 36,
  теряет отрицательный трекинг — правило «минус крупным» привязано к px, не к роли.
- Мера: 60–70ch на десктопе; на мобиле — 100% минус поля, переносы для кириллицы:
  `hyphens:auto` + `overflow-wrap:break-word` (длинные укр/рус слова на 360 — обязательная проверка).
**Антипаттерн:** `font-size:12px` в подписи на мобиле «чтобы влезло»; влезать должно раскладкой.

## R3 · Сетка и сплиты
- Асимметрия 5/7, 4/8 схлопывается в ОДНУ колонку на ≤768. Порядок — контент-первый: текст выше
  медиа, если текст = вход в секцию; медиа выше — только когда медиа и есть сообщение (`order`, не
  дублирование DOM).
- Чередование сторон на мобиле умирает — зигзаг не эмулировать; ритм заменяется вертикальным темпом.
- Карточные гриды: `repeat(auto-fit, minmax(280px, 1fr))`, карточка не уже 280. 3 → 2 → 1.
**Антипаттерн (жёсткий):** горизонтальная карусель вместо стека для контента первой важности —
могила контента. Карусель допустима только для галерей/медиа с явным аффордансом свайпа.

## R4 · Вертикальный ритм вниз
Секции 80–104 desktop → 64–72 tablet → 48–56 mobile (~×0.6). Внутренние отступы в em-логике
пересчитываются сами вместе с кеглем — их не трогать руками.

## R5 · Навигация
- ≤768: 2–3 главных пункта остаются видимыми, остальное — в шит/бургер. **CTA в бургер не прячется
  никогда.**
- Sticky на мобиле дорогая (высота экрана): компакт-режим при скролле вниз, возврат при скролле вверх.
- Футер-колонки → аккордеон или простой стек; мега-жест футера сохраняет иерархию, не высоту.

## R6 · Тач
- Мишени ≥44×44, зазор между соседними ≥8.
- `@media (hover:none)`: у тача НЕТ ховера. Всё, что раскрывается по hover (карточки, тултипы,
  подменю), обязано иметь тап-эквивалент или быть видимым сразу. Ховер-стили за гейтом
  `@media (hover:hover) and (pointer:fine)` (как в panel-canon).
**Антипаттерн:** hover-only раскрытие смысла — на телефоне пользователь не узнает, что там что-то было.

## R7 · Данные и таблицы
≤768: либо карточная раскладка строк, либо горизонтальный скролл С видимой тень-подсказкой и
закреплённым первым столбцом. Шрифт данных не ниже 13px. tabular-nums везде.

## R8 · Формы
Инпуты full-width, лейблы над полем, `inputmode`/`autocomplete` по типу данных, кнопка сабмита
на всю ширину внизу. (Остальное — product-surfaces-canon F-правила.)

## R9 · Медиа и hero
Full-bleed картинки — art-direction через `<picture>` (кадрирование под портрет, не сжатие пейзажа).
Hero на мобиле ≤80svh; `100vh` на мобиле — бан (адресная строка), только `svh/dvh`.

## R10 · Что НЕ адаптируется
Радиус-токены, цветовая система, шкала иконок (16/20/24), микрокопия, focus-visible. Меняется
раскладка и кегль — язык формы остаётся.

<codex>
Codex-специфичные баны:
- Дублирование блока в DOM ради брейкпоинтов (`hidden md:flex` копия того же контента) — один DOM,
  раскладка через grid/order. Дубль = двойная поддержка и рассинхрон правок.
- `w-screen`/`100vw` на вложенных блоках (скроллбар-ширина → горизонтальный скролл на Windows).
- Брейкпоинты «по девайсам» (iphone/ipad-числа) — только наши 360/768/1200 + по контенту, где ломается.
</codex>

## Приёмка адаптива
eyes.py на 360/768/1200 (у нас 390/834/1440 в дефолте тула — считаются эквивалентом) + проверка
кириллицы на 360 (переносы, кнопки, длинные слова) + тач-прогон матрицы состояний (hover-эквиваленты).
Скриншоты трёх ширин — до сдачи, не после.
