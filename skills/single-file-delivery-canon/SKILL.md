# Канон «конфеты» (single-file delivery)

## Что это и зачем

«Конфета» — это инструмент, собранный в **один самодостаточный HTML-файл**: двойной клик — открылся, работает офлайн, без npm, без облака, без CDN в рантайме. Для тула, который едет на выступление на чужой ноут, это идеал доставки: ничего не устанавливать, нечему сломаться по сети.

Но у single-file + вшитых ассетов + лаунчера свои грабли, и все три Роб уже собрал на BRYK: коммерческий шрифт Druk в tracked-source публичного репо (один случайный `git push` от лицензионного инцидента), лаунчер, открывающий что попало с порта, и «пропал звук» — потому что `file://` молча запретил микрофон. Этот канон — чтобы конфета была вкусной и безопасной.

## Место в иерархии

Смежник [[show-safe-canon]]: там build-identity нужна рантайму (провенанс, preflight) — здесь она **рождается на билде**. Кодинг сборщика/лаунчера — терминалу ([[autonomous-build-loop]], [[fable-routine-taboo]]).

## 🔴 Законы

**1. Раздача — single-file, source — сколько угодно.**
Артефакт для человека — **один офлайн-HTML**. Но исходник не обязан быть одним файлом: детерминированный сборщик (`build-standalone.mjs`-класс) инлайнит всё (CSS/JS/ассеты/шрифты) в один артефакт. «Single-file distribution сохранить, single-file source постепенно прекратить» — это не rewrite, а разведение сборки и исходника.

**2. Лицензионные ассеты — НИКОГДА не в tracked-source.**
Коммерческий шрифт/ассет живёт только в **ignored локальном файле**; tracked-source не содержит бинарь шрифта; сборщик инжектит его локально на билде; **pre-push / CI скан блокирует известную сигнатуру и base64-payload**. Урок Druk: `index.html` tracked + base64-шрифт + публичный remote = инцидент в одном случайном пуше. Память оператора («не пушить») — недостаточная защита.

**3. У каждой сборки — своя identity.**
Сборщик пишет `BUILD.json` и инжектит в артефакт глобал/мету: `{product, commit, buildId, standaloneSha256, schemaVersion, buildTime, testedChrome, knownLimitations}`. Это кормит провенанс лаунчера, preflight и «оператор видит buildId» из [[show-safe-canon]].

**4. Лаунчер — часть продукта.**
`file://` **молча** запрещает живые входы (mic/cam/screen-capture — даже промпта нет) и рубит `<script src>` по CORS. Поэтому конфета едет с лаунчером, который поднимает **localhost на ФИКС-порту** (грант разрешения привязан к `origin:port`; плавающий порт терял бы грант каждый запуск), переиспользует живой сервер, и **перед переиспользованием сверяет провенанс** (`BUILD.json`), чтобы не открыть старую/чужую сборку с того же порта. Живой звук — только через лаунчер/сервер, не двойным кликом по файлу.

**5. Одна каноничная упаковка, без двойников.**
Папка пакета названа по build-id: `PRODUCT_2026-07-21_<commit>/` (внутри: артефакт, лаунчер, ЗАПУСК.md, `BUILD.json`). Папки-двойники с той же датой и разным SHA (`… 2`) — граблина: легко открыть или передать не тот файл. Сноси их. SHA раздаваемого файла = SHA в манифесте пакета.

**6. Офлайн — свято.**
Ни облачной зависимости, ни обязательного npm-рантайма на машине выступления, ни CDN в рантайме. Конфета открывается двойным кликом и работает с выключенным вайфаем. Всё, что нужно, — уже внутри.

**7. Модуляризация source не ломает офлайн и ключи.**
Исходник разбирать инкрементально; после каждого шага standalone остаётся автономным и офлайн-способным. **Не** переименовывать массово state-поля и `localStorage`-ключи без миграции, **не** переписывать параллельно рендер и схему данных. Порядок извлечения: метаданные сборки → тяжёлые модули → media I/O → хранилище/миграции → UI-циклы.

## Манифест сборки (`BUILD.json`)

`product` · `commit` · `buildId` (`<date>_<commit>`) · `buildTime` · `standaloneSha256` · `sceneSchemaVersion` · `assetSchemaVersion` · `testedChrome` · `knownLimitations`. Кладётся рядом с артефактом и (частью) инжектится внутрь как `window.__PRODUCT_BUILD__` + `<meta>`.

## Чек-лист лаунчера

Фикс-порт · переиспользование живого сервера · **провенанс перед переиспользованием** (сверка `BUILD.json`, при mismatch — понятное сообщение, чужой процесс не убивать) · `--bind 127.0.0.1` · открывает актуальный entry (не устаревший URL) · окно держит сервер, Ctrl-C гасит · подсказка при `file://`-отказе входов.

## Анти-слоп — чего НЕ делать

- Пушить сборку с вшитым лицензионным шрифтом (или полагаться на «я не забуду не пушить»).
- Плавающий порт в лаунчере (теряет mic-грант каждый запуск).
- Раздавать двойным кликом по `file://` и удивляться, что микрофон/камера мертвы.
- Держать папки-двойники пакета с разным содержимым.
- Тащить облако / CDN / обязательный npm в рантайм машины выступления.
- Открывать сборку с порта без сверки провенанса (можно подсунуть старую/чужую).
- Массовое переименование ключей хранилища при разбиении исходника без миграции.

## 2026-09-10 · экспорт видео и мукс

Срез на 10.09.2026, проверено по npm-реестру и README **внутри тарболлов**. Отвечает на вопрос «как вынуть из канвасной сцены файл, который не дрейфит», не нарушив закона про офлайн и лицензии.

**CCapture.js 2.0.0 — живая библиотека, а не археология.** Опубликована 27.07.2026 тем же автором (spite / Jaume Sanchez) после восьми лет паузы: предыдущий релиз 1.1.0 был 16.04.2018. Переписана полностью — ES-модули, WebCodecs, GPU motion blur, async/await. https://www.npmjs.com/package/ccapture.js

- Форматы: **mp4** (H.264/AV1), **webm** (VP9/VP8/AV1), webm-legacy, **gif** (gifenc), png/jpg/webp в TAR.
- **WebCodecs — путь по умолчанию**: аппаратный, с бэкпрешером, поэтому память при длинном захвате ограничена, а не растёт бесконтрольно.
- 🔴 **UMD-сборка `build/ccapture.umd.min.js` = 116 КБ** — вставляется тегом прямо в конфету. Для нас это ключевое: экспорт помещается в single-file.

**Что CCapture подменяет (детерминированные часы).** `performance.now`, `requestAnimationFrame`, `setTimeout`/`setInterval`, опционально `Date.now` (`hookDate`, включён), `Date.prototype.valueOf` (`hookValueOf`, выключен), `currentTime`/`play` у media-элементов (`hookMedia`, включён).

🔴 **Чего НЕ подменяет — прямой запрет для экспортируемой сцены.** Web Animations API (`element.animate`) и CSS-анимации/переходы идут по часам, которые библиотека не шагает, и при захвате уплывут относительно кадров. Значит: **сцена, которую собираемся экспортировать, анимируется только из rAF-цикла** — никаких `element.animate` и никаких CSS-transition/animation на движущихся элементах.

🔴 **`renderAudioFrames()` — то, что чинит аудио-реактивный экспорт.** Рендерит аудио офлайн и сэмплит AnalyserNode на каждый момент кадра, давая **покадрово точный спектр** — без дрейфа между звуком и картинкой. Плюс можно вмуксить AudioBuffer в выход: AAC/Opus для mp4, Opus для webm. Подробности стороны звука — в [[audio-reactive-canon]].

**GPU motion blur** требует WebGL2 + расширение `EXT_color_buffer_float`; без него — CPU-фолбэк.

⚠️ **Ловушка чтения доков.** README на GitHub master всё ещё описывает старый 1.x (Whammy, gif.js, ffmpegserver) — по нему собирать нельзя. Актуален **README внутри npm-тарбола 2.0.0**.

**Муксеры: старые официально мертвы.** У `mp4-muxer` и `webm-muxer` в манифесте стоит поле `deprecated`: «This library is superseded by Mediabunny. Please migrate to it.» Новое на них не начинать.

- **Mediabunny 1.56.1** (09.09.2026), тот же автор (Vanilagy), **zero dependencies**, tree-shake до ~5 КБ gzip. Есть `CanvasSource` с покадровым `await canvasSource.add(timestamp, duration)`, `AudioBufferSource`, источники из MediaStream. https://www.npmjs.com/package/mediabunny
- Альтернатива: **`canvas-record` 5.5.1** (06.03.2026, MIT) — семь энкодеров, но 🔴 ограничение кадра **9 437 184 пикселя**, что бьёт по 4K+. https://www.npmjs.com/package/canvas-record

**WebCodecs как платформа (что можно обещать).** `VideoEncoder`: Chrome 94 / Firefox 130 / Safari 16.4. `AudioEncoder`: Chrome 94 / Firefox 130 / **Safari только 26**. Экспорт со звуком под старой Safari просто не поедет — рендерить в Chrome.

🔴 **Лицензионные мины — закон 2 не только про шрифты.** Платный сет — это коммерческое использование, поэтому в конфету нельзя инлайнить:

- **Lygia — Prosperity Public License 3.0**: бесплатно только некоммерчески, коммерция = 30 дней триала либо платный Patron. Вдобавок неполное WGSL-покрытие — 657 файлов `.glsl` против 254 `.wgsl`.
- **hydra-synth — AGPLv3**.
- **q5.js — LGPLv3**: при инлайне в single-file накладывает обязательства, а инлайн — это и есть наша доставка.

**Размеры для инлайна (что реально влезает).**

- `regl.min.js` — **85 КБ**, MIT.
- `pixi.min.js` — **800 КБ**, IIFE с глобалью `PIXI`, MIT.
- `q5.js` — **227 КБ** (но LGPLv3, см. выше).
- 🔴 **three.js больше не годится для single-file**: ESM-only, минифицированной и UMD-сборки нет вообще (`three.cjs` буквально пишет «three is ESM-only going forward»), `three.webgpu.js` — 2.2 МБ сырого текста. Для конфеты — regl или pixi.

🔴 **SharedArrayBuffer из `file://` недоступен** — нужны заголовки COOP+COEP, которых локальный файл не отдаёт. Значит wasm-threads и ring buffer на SAB в офлайн-конфете не работают; обмен только через transferable ArrayBuffer.
