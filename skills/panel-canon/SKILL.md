# Panel Canon — как строятся все наши панели

Источник канона: `builder-engine/reference/modules/panel-grammar.js` (контракт флота), CSS-канон хоста client (ритм прописан комментариями), токены EQJ (§17 мастер-плана MUSICVIZ). Этот скилл — их дистилляция в правила, обязательные для ЛЮБОЙ новой панели.

## Закон №1 — ЧИСЛО У КАЖДОГО ПОЛЗУНКА (железное правило Роба)

Каждый `input[type=range]` живёт в паре с `input[type=number]`. Всегда. Без исключений.

- Число **может превышать диапазон слайдера**: ввод значения за пределами min/max НЕ клампится — вызывается `extendParamRange(p, v)`: расширяет `p.min/p.max` И `el.min/el.max` слайдера, чтобы значение реально доезжало до движка. Пользователь имеет право выйти за задуманный тобой диапазон и потом попросить «сдвинь/расширь диапазон» — это фича, не ошибка.
- Слайдер ↔ число синхронизированы в обе стороны (input у range → число; change у number → range + extend).
- Спиннеры скрыты (`::-webkit-inner-spin-button{display:none}`, `-moz-appearance:textfield`).
- `font-variant-numeric: tabular-nums`, моно, выравнивание вправо, формат по step: `+(+v).toFixed(step<1?2:0)`.

```js
// канон extendParamRange (из EQJ, проверен в бою):
function extendParamRange(p,v){ if(!p||isNaN(v))return;
  if(v>p.max){ p.max=v; if(p.el&&+p.el.max<v)p.el.max=v; }
  if(v<p.min){ p.min=v; if(p.el&&+p.el.min>v)p.el.min=v; } }
```

## Закон №2 — ОДНА ГРАММАТИКА РЯДА · СКРАБ-ПОЛЕ

**Эволюция 2026-07-12 (решение Роба, референс Unicorn Studio, EQJ §20.7).** Числовой контрол = **скраб-поле**: один виджет `[ число-в-треке + заливка-позиция + drag-scrub + click→type ]`. Заменяет прежний три-колоночный `label · slider · number` (`1fr 64px 48px`) — число живёт ВНУТРИ трека, а не в отдельной колонке. Почему: закон №1 выполняется по построению (поле и есть число: печатается, превышает диапазон → extend), одна грамматика вместо семи, и высвобождается ширина («выгодное использование пространства» — прямая директива Роба).

Ряд = `label [ⓘ] · scrub`. Никаких самодельных сеток, никаких инлайн-стилей размеров/шрифтов.
- **Взаимодействие:** тянешь по полю горизонтально → скрабишь (клампится к диапазону, Shift = точно); клик без драга → правка числом (Enter/blur коммит, Esc отмена); стрелки ±step на фокусе (Shift ×10); ввод за диапазон → `extendParamRange` (и параметр, и границы поля).
- **Вид:** заливка = `(v−min)/(max−min)` clamp 0..1; число `tabular-nums`, формат по step; спиннеры скрыты; `focus-visible` рамка токеном.
- Тумблер `(0,1,1)` / enum-`select` `.tin` (h24) / `.seg`-пилюли (h30) — как раньше (это НЕ числовые контролы). label overflow ellipsis.
- Скраб-поля НЕ пишутся руками — генерируются одним `mkScrub(cfg)`/`mkRow` из деклараций `[path, label, min, max, step]`. Панель = данные + генератор.
- **Эталон реализации:** `music-viz/mvj-inject.html` → `mkScrub` (number-in-track · pointer-drag · type-exceed · focus-visible, проверен в бою 2026-07-12). Прежний `1fr 64px 48px` допустим только там, где скраб неуместен (широкие числовые пары X/Y — как в Unicorn).

## Закон №3 — ТОКЕНЫ, НЕ ЗНАЧЕНИЯ

Только переменные: тип-шкала `--fz-s/m/l` (9/10/11 mono) · ритм `--sp-1/2/3` (4/8/12: кратно 4, 8 внутри группы, 12 между группами) · моушн `--ease-out cubic-bezier(0.23,1,0.32,1)`, `--dur-press 140ms`, `--dur-pop 180ms` · акценты `--accent-live` (live/audio/активное) и `--accent-warn` (внимание/запись/⚠). Хардкод хекса, px-шага или своей кривой в панели = блок.

## Закон №4 — СТРУКТУРА ПАНЕЛИ

`fieldset` + `legend` (uppercase, --fz-s, letter-spacing .05-.08em, схлопываемые группы, ▸/▾). Дефолтный вид — **Clean** (минимум открыт). Порядок групп в билдере: primary → Motion Pad → Camera → Links → Labels. Тяжёлые/редкие группы — `.closed` по умолчанию. Подсказки — EN-лейблы, короткие служебные слова связаны `&nbsp;` (no-orphan).

## Закон №5 — МАТРИЦА СОСТОЯНИЙ (каждый контрол)

default · hover (только за `@media(hover:hover) and (pointer:fine)`) · focus-visible (видимая рамка токеном) · active (`scale(0.97)`, `--dur-press --ease-out`) · disabled (opacity .42, pointer-events none) · **driven** — параметр под управлением матрицы/модуляции: ряд показывает БАЗУ (редактируемую) и текущее значение (немой индикатор/бар live-акцентом) раздельно — ползунок не дёргается под рукой пользователя · learn/live-режимы — `--accent-live`. Панель без покрытых состояний не сдаётся.

## Донорские паттерны (dat.gui / matter-tools, MIT) — одобренные варианты канона

Перенято Робом из `brm.io/matter-js/demo` (правая панель = MatterTools.Gui на dat.gui). Это ВАРИАНТЫ внутри канона — законы 1-5 действуют для них полностью:

- **Bar-fill слайдер** — вместо трека с бегунком значение показано заливкой полосы (drag по всей полосе). Дефолт для плотных тёмных панелей (perform-режим EQJ): читается с расстояния, выше плотность. Реализация — тот же `input[type=range]`, стилизованный заливкой; number-пара обязательна как везде.
- **Число в ряду — inline-edit:** видимое значение справа И есть инпут (клик → редактирование на месте, как density в dat.gui). Не отдельное поле рядом со значением — само значение редактируемо. Превышение диапазона — по закону №1.
- **LED-toggle** — для ДЛИННЫХ boolean-групп (10+ флагов, как Render в matter-tools): ряд label + точка-индикатор справа, весь ряд кликабелен. Компактнее пилюли `.sw`; `.sw` остаётся для одиночных тумблеров в смешанных группах.
- **Action-row** — действие (load/save/clear/addBody) = полноширинный плоский ряд-кнопка внутри группы, тем же кеглем, что ряды. Не отдельная кнопочная зона.
- **Searchable picker** — длинный список выбора (60+ пунктов): поле поиска сверху + ✓ на текущем. Для библиотек engine-ов/пресетов, когда ростер перерастает один экран.
- **Inspector-tree** — дерево сущностей мира (jstree-паттерн) как отдельный режим навигации по стеку: слои → их параметры/строки. Дальняя вариатива, не для v1.
- **Таксономия групп физ-панели:** Add/Spawn → World (load/save/clear) → Gravity → Engine → Render — порядок групп для физического слоя перенимается как есть.

### Донор №2 — Unicorn Studio (панели Shape/Liquify, принёс Роб)

- **Value-in-bar контрол (главный паттерн):** слайдер и число — ОДИН контрол: полоса с заливкой-значением, цифра inline внутри полосы, клик по цифре = редактирование (превышение диапазона — закон №1), drag по полосе = слайдер. Компактнее пары range+number, дефолт для новых панелей вместе с bar-fill.
- **Сетка ряда «label слева · контрол справа»** (~40/60), лейблы muted, контролы одной ширины правой колонкой — ряды выровнены в два чистых столбца по всей панели.
- **ⓘ-подсказки** у неочевидных параметров (Feather, Spring, Drift) — короткий тултип; НЕ у всех подряд. У нас дополняет hint-футер хоста.
- **Секции внутри панели** — просто вес+отступ (Mix / Animation / Interactivity), без рамок.
- **Табы фасетов** Design | Events у панели объекта → наш аналог: у панели слоя фасеты **Params | Mappings** (строки матрицы этого слоя рядом с его кнобами, а не только в общем рэке) — вариатива.
- **Композитные поля:** XY-вектор одним полем (`X 10.5 · Y -45.8`, оси muted-префиксами) · число+режим (`777 · Fixed ▾`) · цвет = свотч+hex(editable)+× · anchor = 3×3 грид-пикер.
- **Сегмент-контрол** (`X only | Y only | Both`) = наш `.seg`, подтверждён.
- **Таксономия FX-панели** (для FX-слота P4): Main-параметры → **Mix** (easing, radius, invert — как эффект вмешивается) → **Animation** (speed, drift — автономная жизнь) → **Drive** (у них mouse/momentum/spring, у нас audio: feature/attack-release/underlay). Перенимается как порядок групп любого FX.

## Ё-МОЁ (анти-паттерны — на них ревью блокируется)

1. range без парного number. 2. number, клампящий ввод по диапазону слайдера (вместо extendParamRange). 3. Самодельный grid ряда / инлайн font-size / свой gap. 4. Хардкод-хекс или px вне токенов. 5. Спиннеры браузера видны. 6. Ряды, написанные руками вместо декларации. 7. `transition:all`, `ease-in`, анимация layout-свойств. 8. Хвост «потом добавлю число» — числа входят в определение ряда, не в бэклог.

## Чек-лист сдачи панели

- [ ] Каждый range имеет number-пару (программная проверка: `querySelectorAll('input[type=range]')` — у каждого сосед `input[type=number]` в том же ряду)

## Дополнение 2026-08-10 · грабли, на которые уже наступили

### `setValue()` не дёргает `onChange`

Программная установка значения (`DG.panel.setValue(path, v)` и аналоги) обновляет ОТОБРАЖЕНИЕ ряда
и внутреннее состояние кита, но **не вызывает обработчик изменения**. Значит сцена о ней не узнает.

Симптом: панель показывает одно, сцена живёт другим. Особенно больно в харнессе и при вождении
сцены снаружи (лендинг, скролл, пресеты) — тесты «зелёные», а картинка не менялась.

**Правило:** у сцены есть свой вход в состояние (`Scene.set(path, value)`), который делает обе вещи —
пишет в состояние И отражает в панели. Снаружи ходить только через него. `setValue` — для зеркала
(например, когда меняется выделенный объект и ряды должны показать его личные значения).

### Ряды-зеркала выделенного объекта

Если панель правит «текущий выделенный» элемент, при смене выделения ряды обязаны перерисоваться
его значениями. Иначе первый же поворот ручки применит к новому объекту значения старого.
Механика: на смену выделения — прогон `setValue` по всем рядам группы из личных настроек объекта.

### Числовой инпут: потолок движка ≠ клампу

`extendParamRange` обязан пропускать значение за пределы слайдера — это закон №1. Но у движка
может быть физический потолок (память, число тел). Тогда потолок держится ВНУТРИ движка
(`Math.min(MAX, value)`), а не в панели. Ввод доезжает, панель честна, движок не падает.

## Дополнение 2026-08-10 (вечер) · галерея анимаций знака, 42 панели на странице

### 🔴 Мёртвая ручка — это обман, а не запас

На галерее знака оказалось, что у **30 приёмов из 42** ряд «характер» (выбор кривой) не подключён
к коду вообще: крутишь — ничего не происходит. Ряд существовал «на будущее».

**Правило:** ряд показывается только там, где параметр реально читается. Проверяется программно,
не глазом — по исходнику функции:

```js
function usesEase(f){
  if(f._ue == null) f._ue = /easeOf\s*\(\s*P\s*\)|P\.ease/.test(String(f.apply));
  return f._ue;
}
// в сборке панели:
var decls = (f.params||[]).concat([['@tempo','темп', 0.1, 6, 0.05]]);
if(usesEase(f)) decls = decls.concat([['@ease','характер', EASE_NAMES]]);
```

**Стенд «мёртвых ручек»** (`dead.mjs` из `motion-kinematics-canon`): для каждого параметра
прогнать состояние по сетке времени при min и при max, сравнить траектории. Совпали — ручка мёртвая.
Сериализовать надо ВСЁ состояние, включая массивы (лучи, второе тело, след), иначе будут
ложные срабатывания на приёмах, где параметр меняет только содержимое массива.

### «Вернуть дефолты» обязан пересобрать панель

Классическая полу-починка: сброс пишет значения в состояние, а ряды продолжают показывать старое.
Пользователь видит 17, движок работает с 13.

```js
FX.forEach(function(f){ /* … вернуть значения … */ });
cards.forEach(function(c){ buildPanel(fxById(c.id), c.host); });   // ряды пересобрать
layout(); fitCards();
```

Заодно: сброс возвращает **личный** дефолт приёма (`f.ease0`, `f.tempo`), а не общий —
иначе «вернуть дефолты» ломает приёмы с собственным характером.

### Value-in-bar: число ВНУТРИ дорожки

Когда панелей на странице десятки, пара `range + number` занимает слишком много ширины.
Рабочий вариант канона (донор Unicorn Studio, закон №1 соблюдён полностью):
полоса с заливкой-значением, цифра inline справа внутри полосы, drag по полосе = слайдер,
клик без движения = редактирование числа.

Ключевая грабля: **инпут перехватывает pointerdown** и драг не работает.

```js
// инпут выключен для указателя, включается только по клику без движения
tr.addEventListener('pointerup', function(e){
  if(drag && !drag.moved){ num.style.pointerEvents = 'auto'; num.focus(); num.select(); }
  drag = null;
});
num.addEventListener('blur', function(){ num.style.pointerEvents = 'none'; /* … */ });
```

Край дорожки — не бетонный: за пределами диапазона тянется с сопротивлением
(`rubber(over, dim) = over*dim*c / (dim + c*|over|)`), а `set()` расширяет диапазон по закону №1.

### Синглтон-кит не тянет десятки панелей

Готовый кит панели (kit-panel и подобные) держит ОДНУ активную панель: при второй сборке
первая перестаёт отдавать `onChange`. Проверяется на стенде за минуту.
Для страницы с панелью в каждой карточке — свой рендер ряда по грамматике канона
(это не «самодельная панель», грамматика та же: декларации → ряды, число у каждой дорожки,
extendParamRange, состояния).

### 🔴 Инвариант пишется по ПРЕФИКСУ, а не по классам одного файла

Инвариант из §«Верификационный инвариант» написан под `.scrub/.sval`. Кит использует
`.dg-scrub / .dg-scrub-val / .dg-scrub-edit`, воркеры — свои префиксы. Гейт, списанный
с того инварианта, **не увидит ни одного скраба кита** и будет вечнозелёным.

```js
// у каждого скраба любого префикса есть видимое число и поле ввода
[...document.querySelectorAll('[class*=scrub]')]
  .filter(e => !/-(val|edit|fill)$/.test(e.className.split(/\s+/).pop() || ''))
  .forEach(s => {
    if (!s.querySelector('[class*="-val"]')) throw new Error('скраб без числа: ' + s.className);
    if (!s.querySelector('[class*="-edit"], input')) throw new Error('скраб без ввода: ' + s.className);
  });
// сырых range в панели ноль
if (document.querySelectorAll('input[type=range]').length) throw new Error('orphan range');
```

### 🔴 Диапазон объявляется в aria, иначе он непроверяем

Скраб несёт `role="slider"`, `aria-label`, `aria-valuemin/valuemax/valuenow`,
и `extendParamRange` двигает `aria-valuemax` вместе с `p.max`. Диапазон, расширенный
только внутри объекта, снаружи неотличим от клампа: ни скринридер, ни гейт не могут
ни озвучить ручку, ни проверить закон №1. По флоту сегодня: 24 скраба у D2 и ни одного
`aria-valuemax`.

Функциональная проба (`gate.py --only 2-extend`) вводит `max × 1.5` и требует двух вещей:
`aria-valuemax` расширился **и** КАДР изменился. «Доехало до движка» доказывается кадром,
а не показанным числом: панель и сцена расходятся молча.

### Ещё два вида ряда

- `tabs` — `['path','Label',[опции],'tabs']`: один выбор во всю ширину ряда.
- `chips` — `['path','Label',[опции],'chips']`: МНОГО выборов, значение массив.

Оба взяты из панели конструктора наклеек (`buildSeg` / `buildChips`), грамматика ряда
не менялась. Флаг `{studio:true}` последним элементом декларации убирает ряд из
клиентского режима: в `client` он не строится вовсе, а не прячется стилем.

### Дефолт живёт в декларации

Плоская форма — `[key, label, min, max, step, default]`, шесть элементов. Без шестого
дефолтом становится `min`, и сцена рождается пустой при любом `min > 0`: на образце
арсенала это выглядело как «сид не влияет на кадр» и «холст пуст».
